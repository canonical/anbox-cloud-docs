# 1.31.0

These release notes cover new features and changes in Anbox Cloud 1.31.0.

Anbox Cloud 1.31.0 is a minor release. To understand minor and patch releases, see {ref}`Release notes <ref-release-notes>`.

Please see {ref}`Component versions <ref-component-versions>` for a list of updated components.

## Requirements

See {ref}`Requirements <ref-requirements>` for details on general and deployment specific requirements to run Anbox Cloud.

## New features & improvements

### Projects

{ref}`Projects <exp-projects>` group instances within an Anbox Cloud deployment and provide project-level access control and network isolation. Every instance belongs to a project. If you create an instance without specifying a project, AMS places it in the built-in `default` project. On upgrade from a release that predates projects, AMS also moves all existing instances into `default`.

You can {ref}`manage projects <howto-projects>` with the new `amc project` commands or from the dashboard. For access requirements, see {ref}`the project authorization model <sec-project-authorization>`.

### Multi-display

Anbox Cloud now supports {ref}`multi-display <exp-multi-display>` for {ref}`virtualized Android <exp-android-execution-models>`. A single instance can have up to four displays, each with its own content, resolution, density and frame rate.

Displays are configured when the instance is created, using `amc launch` or the dashboard. When streaming is enabled, all displays are carried in one streaming session as separate video tracks. The dashboard and Anbox Streaming SDK support presenting and interacting with each display.

The {ref}`stream controls bar <ref-stream-controls-bar>` in the dashboard has been rearranged for multi-display streams. Controls are now grouped into instance and Android controls, which apply to the whole instance, display-specific controls, which apply to the focused display, and session utilities.

### Android 17 for virtualized Android

Anbox Cloud now provides Android 17 images for the {ref}`virtualized Android <exp-android-execution-models>` execution model. New `resolute:android17-cf:*` (AOSP) and `resolute:aaos17-cf:*` (AAOS) images are available on both `amd64` and `arm64`.

### Control plane members

Charmed Anbox Cloud deployments now support designating a fixed set of LXD cluster members as {ref}`control plane members <sec-clustering-control-plane-members>`. This ensures that autoscaling and node scale-down operations never accidentally remove a member participating in database consensus or drop the cluster below quorum.

### Accessibility

The dashboard includes many accessibility improvements, including keyboard navigation, focus management, screen reader support, heading structure and color contrast.

### Other

- New appliance and charmed deployments now default to LXD 6.
- Instances using {ref}`virtualized Android <exp-android-execution-models>` images now use the host GPU for rendering when the instance has an NVIDIA GPU.
- The display pipeline of the Anbox runtime streaming for virtualized Android images has been optimized for software rendering.
- The rendering pipeline of the Anbox WebRTC platform has been optimized for NVIDIA GPUs.
- Initial support for Juju 4.0 has been added to Anbox Cloud charms. The `coturn` charm is not yet supported with Juju 4.0. The `etcd` and `easyrsa` charms are deprecated and Juju 4.0 support will not be added to them. Use [`charmed-etcd`](https://charmhub.io/charmed-etcd) to replace `etcd` and [`self-signed-certificates`](https://charmhub.io/self-signed-certificates) to replace `easyrsa`.

## Removed functionality

- The dashboard no longer supports managing multiple subclusters.

## Deprecations

Support for `anbox-connect` is deprecated as of 1.31.0 and will be removed in 1.33.0. All its usages have been replaced with `amc connect`. See {ref}`sec-anbox-connect-deprecation` for details.

## Known issues

- You need to make sure to upgrade your Anbox Cloud deployment to 1.31.0 or later before upgrading LXD to 6.10 and later. Not doing so might result in NVIDIA GPU instances being unable to start until AMS is upgraded.

See our [open bugs in Launchpad](https://bugs.launchpad.net/anbox-cloud/+bugs?field.searchtext=&orderby=-importance&field.status%3Alist=NEW&field.status%3Alist=CONFIRMED&field.status%3Alist=TRIAGED&field.status%3Alist=INPROGRESS&field.status%3Alist=INCOMPLETE_WITH_RESPONSE&field.status%3Alist=INCOMPLETE_WITHOUT_RESPONSE&assignee_option=any&field.assignee=&field.bug_reporter=&field.bug_commenter=&field.subscriber=&field.structural_subscriber=).
